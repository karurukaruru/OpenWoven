# OpenWoven

[English](README.en.md)

## 什么是 OpenWoven？

OpenWoven 是一个 AI 聊天软件。你可以通过它和 LLM 交流，应用会在交谈中逐渐记录你的喜好和交流习惯，让后面的回复更了解你一些。

其中负责学习用户的系统叫 AUL，AI User Learning。除了聊天，它也有记忆、消息分条和主动发送这些功能。目前已经做了安卓端应用。

## 快速开始

安卓端需要 Android 8.0 及以上，使用你自己配置的模型 API。

1. 打开应用，回答初始问题，先建立用户和角色的基本设定。
2. 在设置里填写接口地址、API Key 和模型。
3. 可以让当前模型生成角色设定和昵称，预览确认后开始聊天。
4. 如果需要主动消息和通知，允许通知权限，再按自己的习惯调整发送次数和免打扰时间。

模型需要自己提供，调用可能产生费用，相关聊天内容会发给你配置的服务商。

APK 目前还没有挂到 [Releases](https://github.com/karurukaruru/OpenWoven/releases)。想先用的话可以按 [源码构建说明](CONTRIBUTING.md#android) 构建安装；有下载包后会补在这里。

## AUL 是什么？

AUL 是给 AI 使用的用户学习系统，思路是在我之前的 [ASM（Agent Software Map）](https://github.com/karurukaruru/agent-software-map) 基础上修改、迭代而来的。

ASM 记录的是 Agent 使用软件时需要知道的东西。到了这里，记录的对象换成了用户：用户大概是什么样的人，喜欢什么，不喜欢什么，希望别人怎么和自己说话。

同时，应用也会保存 LLM 应该扮演的角色。一个是“它应该是什么样的人”，另一个是“对面是什么样的人、想怎么聊”，两边分别记录。

比如用户喜欢短一点的回复，能接受互相损两句，但是心情不好的时候不想一直听建议。这些就可以慢慢记下来。之后聊天时，LLM 会结合这些信息和当前的状态来回复。

AUL 有一个初始状态。用户在交流中表现出偏好、对某种行为的厌恶，或者明确说“太长了”“别一直追问”，应用就把这些信号记录下来，更新 AUL。下一次对话再读取新的 AUL，然后继续调整。

说白了就是：先有一点了解，聊完以后改一点，下次再用。某种程度上，AUL 也是一种记忆，只是更偏向用户画像和交流习惯。

### 初始 AUL 怎么形成？

前置是十道题，五道了解用户，五道了解希望它扮演的角色。完整版是五十道题，可以后面再补，不确定的不用硬填。

五十这个数量没有什么严谨的科学依据，只是我觉得这些问题应该能先形成一份初始 AUL。题目也不是我一道一道出的，我只说了大概方向，其余交给 GPT 和 Codex 整理。

问卷只是开头，不是填完就把用户定义好了。用户后面可以修改资料、反馈回复，也可以直接在聊天里纠正它。角色的设定和已经说过的经历也会保留，尽量让前后聊起来能对得上。

## Memory 怎么做？

现在主要按日、周、月整理聊天记录：每天整理当天聊了什么，一周结束后整理这一周，一个月结束后再整理这个月。这里按日历周期处理，不是每个月都硬凑三十天。

原始聊天记录也会保留。以后提起以前聊过的东西，可以按日期和关键词找相关摘要，再找回那时候的原话，不用每次把全部历史塞进上下文。

当前摘要是应用根据已记录的信息和原话整理的，不会每天额外调用一次 LLM 做总结。以后是否换成模型摘要，再看实际需要。

## Talk：更接近日常聊天

Talk 界面就是一个简单的聊天界面。我参考的主要是中国大陆和香港比较日常的发消息方式：很多时候是一句话分几条发，后面想到什么再补一句，而不是一次把所有话写成一篇小作文。

所以这里主要做了几个处理。

### 等用户说完再回复

用户连续发出的几条消息，会放在一起理解。

输入框里还有字、还在拼字的时候，先不回复。发送以后，如果没有继续输入、点击输入框等动作，默认等二十秒再交给 LLM。等待可以设置为十到六十秒。

这里只观察本应用的聊天输入框，不读取其他应用的键盘内容。

### 回复也分条发送

日常回复会按意思拆成几条独立消息，不是给同一条消息加几个空格。

几条之间通常隔一两秒，长一点的句子会多等一点，不会一下把所有消息同时弹出来。默认也尽量让日常回复短一点、口语一点，想聊得详细些可以在设置里调。技术说明、代码或者明确要求的长文不强行照这个方式拆。

### 开场白延迟和主动消息

可以开启开场白延迟。比如单独发一句“在吗”，它可以隔一到三分钟再回复；这个选项默认关闭，也不是所有消息都要额外等这么久。

它也可以自己发消息过来。聊了一段时间后，应用会结合近期话题、兴趣和主动程度，安排下一次轻量的开场。到时间时，如果没有被新的聊天取消，并且满足发送条件，就生成内容发过来。

这不是固定“停聊十分钟就发”。次数、间隔和免打扰会影响安排，用户继续发消息时旧开场也会取消，不一直催着用户回复。主动开场同样会分条发送。

另外也能自己预约：指定一个时间，发送原文，或者到时候让模型围绕某个话题发消息。

目前没有接 Google FCM，使用安卓后台服务和系统任务调度，再发系统通知。手机的省电和后台限制可能影响发送时间。

## 图片和其他设置

在模型设置里，可以声明这个模型是否支持看图。模型确实支持的话，就能在聊天输入栏选择图片发送。

目前只能由用户发送图片，还没有让对面的角色主动发图，也没接图片生成。以后可能会做，但现在先把文字聊天弄好。

回复长短、主动程度、等待时间和学习参数等都可以调整。AUL 的独立导入、导出功能目前也还没做。

## 核心机制

聊天和学习是连起来的：

```text
读取 AUL、角色设定和相关记忆 → 形成本轮回复策略 → LLM 回复
保存对话与反馈 → 提取偏好和状态信号 → 更新 AUL → 下次对话再读取
```

当前明确的偏好和纠正主要用规则、反馈来识别；可选的模型分析可以补充一些信号。识别到的信号先保存，再合并进 AUL，并不是每句话都额外请求一次模型来重写整个画像，也不修改底模的权重。

对话记录、用户偏好和角色经历分别保存。每轮只取需要的部分，让模型知道现在该怎么聊，以及之前有哪些相关的事情。

想看具体实现，可以看 [AUL 说明](AUL_DESIGN.md)、[记忆说明](MEMORY_DESIGN.md) 和 [架构](ARCHITECTURE.md)。

不接 API 也可以先跑偏好学习演示（Python 3.11+）：

```sh
python -m pip install -e .
python -m openwoven --db ":memory:" demo
```

演示用的是示例回复，不是真实模型。

## 项目结构

```text
android/                  安卓应用，聊天界面、设置和通知
src/openwoven/            Python 使用入口
src/adaptive_companion/    AUL、记忆、聊天策略和消息调度
prompts/                  角色生成提示词
examples/                 记忆与检索演示
tests/                    核心回归测试
```

目前大体能跑，但我自己也没认真用多久。AUL 到底有多大效果，长期记忆整理多次以后能不能记清楚，这些还得后面实际用。
